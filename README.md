# 科学家解答服务网（房间开启制）

无需注册、无需登录，填写昵称即可进房。**所有房间默认关闭**，只有知道自己房间号的访客能进——但进房后是否可以发言，取决于房间是否已开启。

## 房间开启制

- 每个房间都有「开启 / 关闭」两种状态，状态保存在 MQTT 保留消息上，后来者一进房就能知道
- 开着：正常群聊（文字 + 图片，在线成员列表）
- 关着：聊天区会被「房间门」覆盖，看到三种选择：
  1. **付费订阅自动开启** — 房间里嵌有 PayPal 订阅按钮（$2/月）。付款成功后房间立即自动开启
  2. **免费提交申请** — 填一段留言发给科学家，科学家收到 GitHub Issue 通知，在管理面板点一下即可开启
  3. **已付费用户恢复** — 之前订阅过但房间被关，用本机保存的订阅记录一键恢复开启

## 房间管理网关（科学家的后台）

跑在科学家自己电脑上的 Node 程序 `room-gateway.js`：

```bash
npm install        # mqtt 依赖
node room-gateway.js
```

- 打开 **http://127.0.0.1:8899** 就是管理面板：
  - 待处理申请列表（房间号 / 昵称 / 时间 / 留言），点「✅ 开启房间」或「❌ 拒绝」
  - 已开启房间列表，可一键「⛔ 关闭房间」（付费用户仍可在页面上自行恢复）
  - 手动开启任意房间号
- 收到申请时自动在 `lianchuzhong/ppe` 创建 GitHub Issue 通知，Issue 里带一键开启/拒绝链接（只在本机 127.0.0.1 有效，别处点击无效果）
- 处理过的申请自动清掉 MQTT 保留消息、关闭对应 Issue；重启后靠 `rooms.json`（脚本同目录）里的已处理 id 去重，不会重复通知
- GitHub 令牌从**脚本同目录 `config.json`** 读取（兼容旧版 `~/Desktop/ppe/config.json`、`~/桌面1/ppe/config.json`），环境变量 `GITHUB_TOKEN` 优先
- 测试：环境变量 `LCZ_ISSUES=off` 时不创建真实 Issue；`LCZ_CHATLOG=off` 可关闭控制台聊天日志

## 技术实现

- 公共 MQTT broker（emqx / hivemq）+ 保留消息：
  - `succession/<房号>/control` — 房间开关状态（管理员或付费自动发布）
  - `succession/<房号>/request` — 免费开启申请（网关处理后清掉）
  - `succession/<房号>/chat` — 直发直收聊天（不再有逐条审核）
  - `succession/<房号>/presence/<id>` — 在线状态与心跳
- 纯静态页面，GitHub Pages 托管；esbuild 打包
- PayPal 订阅按钮懒加载，SDK 加载失败时降级为纯订阅链接

## 安全边界（如实说明）

- 状态里的 `k` 校验钥匙写在公开页面里（与网关一致），**防误触不防恶意**：懂技术的人可以伪造「开启房间」，也可以在房里发言。这不是银行系统，防的是误操作和路由误发
- 聊天走公共服务器的临时通道，不落库、无历史存储，但全程是明文消息体
- 管理接口只监听 `127.0.0.1:8899`，并且带独立签名校验，外部设备无法点开
